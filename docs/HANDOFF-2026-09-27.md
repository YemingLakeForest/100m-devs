## 2 · Standing rules (carry these into every session)

- **Work here, in `100m-devs`, on `proof/three-garage`.** Push stable batches with
  `git push origin proof/three-garage:main` — *"when you have something stable, I want you to do a push to main on old
  repo so I can have a play"*. `main` deploys the web build (`.github/workflows/deploy-web.yml`) to
  https://100mdevs.mercilessstudio.com.
- **The rebuild is read-only reference** — *"no more live changes"*. Its source is copied in under `src/three/`
  (mirroring its folders), and the copy is the one that changes.
- **Mechanics canon is the rebuild; art-style canon is this repo** (`docs/ART_DIRECTION.md`, STUDIO_OS, the CRT
  post-process). A system brought across is redrawn in this language; its rebuild UI is reference only.
- **The GDD here (`GDD.html`) is amended in place** when the user overrides it: quote them, mark
  `[amended YYYY-MM-DD]`, keep the argument. The rebuild's GDD is newer on mechanics and is the source for them.
- The game never calls the network. Debug seams (`?full`, `?trees`, `?devs`, …) are loopback-only.
- ElevenLabs is metered: generate music only with the user's go (and the account needs a paid plan).
- **禁止穿模 (no clipping) is release-blocking.** Nothing automated checks it; look, and say what you looked at.
- Never edit files or `git stash` while `npm run test:ui-frame` runs: it serves the working tree.
- `npm run check` is lint + types + unit tests + art check + the UI frame gate. It says nothing about how the game
  looks: open the game (`npm run dev`, then `http://127.0.0.1:5173/?notitle`, `?full` for a prestiged studio with the
  whole cast) and say exactly what was checked.

## 4 · What changed in this game this session (2026-09-26/27)

**The upgrades are the per-person trees.** *"I thought upgrades are trees"*, *"retire the old tree, but the story of
james introducing us instant messenger should be how upgrade trees are introduced"*.
- **Retired:** the studio tech board (the rail's UPGRADES and `hud/UpgradeBoard.tsx`), the founder's Management tree,
  and the shared hero skill board with hero XP and levels. `sim/techTree.ts` and `sim/founder.ts`'s tree are kept only
  as effect vocabularies: a tree node names an old effect with `TreeNode.tech` and `store.techOf` folds it.
- **Wired in the trees:** Serena's pipeline nodes; **Instant Messenger is the root of James's tree** (communication
  load −5%, from the first Paradigm Shift, as the old grant was); **the Daily Standup is the root of Billy's tree**
  (his scene is him bringing it). Every other node can be bought and does nothing, and says NOT IN THE GAME YET.
- **Doors:** a person's card has UPGRADES (your panel for yours), only after the first Paradigm Shift, only for someone
  who has arrived; the window shows **one tree**, with no heads row. James's Instant Messenger scene now ends on his
  tree opened at that node (the trees' introduction). THE THREAD's OPEN UPGRADES opens James's tree with his one-line
  instruction; any tree purchase clears the thread. The founder-board scene ends on your tree.
- **Future (user's ask, in the GDD §11):** *"I still want company wide upgrade tree, potentially can be something
  visible to the scene (debug rubber duck for example)"*. Not designed yet.

**Hero placement is cut.** *"Some mechanics in the old game I want remove, hero placement, different types of hires
(SRE QA ETC."*
- A hero works for the whole studio from the day they arrive (`sim/heroRoster.ts`, full share). Gone: posting,
  recall, the roster strip, desk plates, coverage paint, the bench, the remote-assignment scene.
- Billy keeps half the floor coding through the stand-up; Melany bills a dollar per developer a second.
- James's promotion (*Global Head of His Desk*) fires on his first colleague instead of a rung.
- The rating's hero term is now how much of the cast has arrived; its traits term is zero until trees are wired.

**Typed hires are cut.** Every hire is a developer; the dial is one row. Mo halves defects, Serena puts 1 in 50 of the
headcount on call for incidents, Matt 1 in 20 on the help desk for tickets; before them the founder carries both.

**The hero card is redone** (`hud/HeroCard.tsx`): the pass, what the person is doing right now (live rows from the
fold), UPGRADES, and ← → to the next person. TEAM opens it on James; the belt opens Serena's.

**Saves:** old documents' `roster`, `hireRole`, `heroPlacements`, `tech`, `heroXp`, `heroNodes` and `founderLevels`
are ignored on load. No version bump.
