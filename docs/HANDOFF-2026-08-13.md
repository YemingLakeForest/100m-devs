## What is left of it

Two things, and the first is the one that matters.

### 1. Nobody has seen the fix on the handset that reported it

Every defect in this batch was reported **off a device** and every fix was verified in **headless
Chrome** — five frame sizes, screenshots at 816×366 and 997×448, and the gate re-run with two of
the defects deliberately reintroduced so it could be watched failing. That is a strong check and
it is not the same check.

What headless Chrome does not have: a **real soft keyboard** (the gate simulates one by shrinking
the viewport, which is a model of a keyboard and not a keyboard), **dpr 2.25**, Android's font
metrics, and whatever text-size preference the reporting phone is set to. R48 in particular was a
bug about what a keyboard does to a viewport, and it is being called fixed on a simulation of one.

**Do this before building anything else.** It is one build and five minutes, and the whole batch
is provisional until it happens.

The request was *"QA and SRE **and other story and their mechanics** come after the first
prestige."* The mechanics half is done and enforced. The story half is done **by exhaustion**: the
only story that exists today is James's arrival and the Instant Messenger handover, and after this
batch those sit either side of the door exactly as asked.

The five §21.7.3 hero arrivals and the §21.7.4 promotion **do not exist yet** (Phase 6, below).
When they are written they inherit the gate for free — every one of them fires on a hero, heroes
are §13.6, and §13.6 has always been behind the shift. So there is nothing to do now, and there is
something to *not get wrong later*: **no scene authored from here on belongs in Run 1.** Act I is

## Four things this session changed about that work

Every phase above adds elements to a rail or a screen this batch has just finished measuring. None
of these are suggestions.

**1. The rail budget is spent to the pixel, and §10.1a now says so in writing.** At 997×448 the
right rail wanted 649 px against 426; at 748×336 the left wanted 478 against 314. Both fit exactly
now. **Anything new in a rail has to name what gives way**, in §10.1a's stated order — second
readings before first ones. There is no slack left to absorb a component that does not.

**2. The gate runs in `check` and checks overlap — but its component list is still an
allowlist.** That was hole #3 of four in §25.7.3 and it is *mitigated, not closed*: `COMPONENTS`
and `PAINTED` in `scripts/ui-frame.acceptance.mjs` are hand-maintained. **A new HUD or board
component that is not added to them is invisible to the gate**, and will pass while overlapping
everything. Add the selector in the same commit that adds the component.

**3. New systems default to Run 2+.** `currentUnlocks()` in `store.ts` is the single reader; a
system that should be live in Run 1 is now the case that has to argue for itself. And in tests:
**`__resetStore()` clears permanent state too**, so a mid-test reset silently drops you to Run 1
and your assertions measure 0 against 0. `backlogs.test.ts` and `Hud.test.tsx` both carry a
`prestiged()` helper — copy it rather than rediscovering this.

**4. `?full` is how a full HUD gets looked at.** It sets `paradigmShifts: 1`, twelve developers,
a shipped catalogue, 37 defects, a live incident and 400 tickets. Every screenshot of Phase 4's
board should be taken through it, because a board reached from a fresh save is a board with
nothing on it.

## Traps 19–23 — for the register in `HANDOFF.md`

**19. No vitest test in this repository can see a layout defect.** jsdom has no layout engine;
`getBoundingClientRect()` returns zeroes. 1,267 tests passed through every bug in this batch and
were not at fault and could not have been. **vitest owns behaviour, the browser gate owns
geometry**, and that division only works if the browser gate runs — which is why it is in `check`
now. Do not write a test that asserts on a rect.

**20. `min-width: auto` is the default on every grid and flex item, and it is a lie.** Six of the
seven defects were the same sentence: *a container was allowed to be smaller than its contents.*
Four equal columns and a nine-character label gave `MOUSTACHGOATEE`; two levels of it printed a
release name across `OFF SALE`. **When a track can receive text, it is `minmax(0, 1fr)` and the
item is `min-width: 0`** — and if a count of columns is wanted, make the count a *ceiling* and
take the floor from the labels (`optionFloor()` in `FounderSetup.tsx`).

**21. In `app.css`, position beats intent.** A rule of equal specificity later in the file beats a
media query earlier in it. The short-frame `.backlog` trims were first written into the
`max-height: 470px` block at ~line 1485 and had **exactly zero effect**, because `.backlog` is
defined at ~2438. The file already warned about this for buttons — there is now a "part three" at
the end of it. **Short-frame overrides go at the end of the file, always.**

**22. `git checkout <file>` to undo a probe patch reverts everything uncommitted in that file.**
Used to remove a deliberately-broken CSS rule after a negative test; it took the session's entire
`founderSetup.css` with it, all of which had to be re-applied from memory. **Patch a negative test
in with a targeted string replace and take it out with the reverse replace.**

**23. `jumpToPhase` replaces the whole run.** It calls `freshRun()`, so any `__setState` *before*
it is discarded. A test that set up a studio and then jumped to a phase measured an empty one. Set
the phase first, the state second — and see trap 5, which is the same seam biting differently.
